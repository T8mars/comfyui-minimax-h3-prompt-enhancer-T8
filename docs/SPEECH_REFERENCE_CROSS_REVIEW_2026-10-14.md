# 可选语音参考：追加 20 轮交叉检查

2026-10-14，用户要求开发完成后再由子 Agent 交叉检查、复现并修复 BUG。本轮主 Agent 检查输入／ASR／前端，子 Agent 独立检查输出／纠正／兼容；分批交换反例，最终由主 Agent 重跑。不是将同一测试重复 20 次当作 20 轮。基线仍为 1.31.1，未提交、推送、改版本或重启用户服务；第一阶段的 [真实测量与失败](SPEECH_REFERENCE_ACCEPTANCE_2026-10-14.md) 保留。

## 已复现并修复

输入与前端六类：

1. **字幕 ID 丢失**：导入 SRT 编号／VTT cue ID 被重命名，按原 ID 指派角色失败。现在保留 ID，重复 ID 明确拒绝；数字 SRT 编号可保留，非数字 ID 通过 JSON 保留。
2. **来源切换被非活动缓存阻断**：从已有字幕切到 AUDIO 后，隐藏但保留的旧文字触发冲突；非活动媒体被其他节点提前缓存时也会触发，导致冷热缓存行为不同。现在显式 source_mode 只读取活动来源，不清空用户缓存，不混入或执行未选输入；缺失活动来源仍拒绝。
3. **单音流组件的音轨索引错误**：VIDEO 组件内部是一条 AUDIO，却可携带 audio_track=1 发请求。现在在访问服务前拒绝；普通文件型视频的多音轨功能不变。
4. **人工偏移丢词／错钟**：服务先加 offset，helper 又按原时窗过滤，偏移后可能失去已选句；裁剪 AUDIO 的负偏移还可能在映回源起点前成为负时间。现在服务接收 offset=0，先在源时钟选完整句，再本地偏移一次。负起点截 0 并复核；整句落在 0 之前明确报错，不静默删词。
5. **字幕标签被当原词**：带 voice／排版标签或实体的 cue 被原样接受为发声文字。当前明确支持纯文本 SRT/VTT，格式化字幕须导出纯文本或校对 JSON，不泛化剥标签、不猜 `<v>` 角色。plain 来源中的原始比较符不改写。
6. **只读状态误报就绪**：组件 supported=true，但当前 CUDA 或缺 CPU guard 时仍显示 Ready。现在同时满足 CPU、guard、supported 才就绪；已有字幕隐藏无效的 ASR 高级设置，但保留其值。

输出侧六类，均先写失败反例再修复：

1. 标题／画面上的 `{原句}`、English `sign/title says` 被误算为实际发声；仅明确展示语境排除，未知原生花括号仍按对白。
2. “不要说／禁止复述／Do not say”的引号或花括号被误算为额外对白；按最近谓词的否定关系判断。
3. “听到铃声后说出……”因前面的 hearing 被漏掉新增发声；较近的明确 say 必须计入。
4. 隐式 `__context__` 包装的取消被当普通纠正错误；同时覆盖显式 cause、真实 Comfy `InterruptProcessingException`（BaseException）、InterruptedError，原样传播，普通异常仍脱敏。
5. 主提示词原生 Seedance `{对白}` 未被视为用户授权，reference 模式误触发纠正；现在按 Seedance 原生解析授权，而非 H3 引号规则。
6. 已有花括号对白后，无引号“他又说：新句。”漏检；单独解析明确裸发声谓词，不把声画对应说明误算成台词。
