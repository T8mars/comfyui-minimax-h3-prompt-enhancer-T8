# H3 说话人格式自动修复

日期：2026-10-04。功能在 1.29.0，证据发布修正在 1.29.1；下述测试不是 Registry 审核通过证明。

## 问题与修复

H3 原生发声写法如 `Alice (S1) says: <d>[English] Wait.</d>`：
编号在台词块外，语言标签是英文语言名，块内原台词不得改写或翻译。
实际模型会写成全角 `（S1）`，或在角色与台词已明确时漏掉编号。
此前只有显式 Quality Repair 才进行本地格式修正，Off 直接返回这些错误；
重复强调提示词仍无法保证格式。这是输出合同执行缺口，不该只让用户加设置。

现在 `h3_vocal_protocol.py` 在公共输出边界自动处理，覆盖本地 GGUF/API、
所有 H3 表演模式及质量 Off/Check/Repair，不额外调用或静默开启付费纠正：

- 将真实发声注解中的全角括号/分隔符改为 ASCII，保留原有编号。
- 单个无竞争来源的发声事件，或具有明确原句/姓名/Subject 绑定的漏号，
  按实际发声顺序补号；同一明确来源复用编号，已有源 ID 如 S7 不重新编号。
- 仅校正已知显式语言名别名，如 `[中文]` → `[Chinese]`，不猜语言或译台词。
- 不改实际台词、引号画面字、镜头/时间码、元数据和素材编号；
  `<Subject 2>` 不等于第二位说话人，静默角色与 Audio-only 歌词提示不新增 ID。
- Relay 仅处理 `native_prompt`；不把 H3 规则塞进 `global_prompt`、
  `events[].prompt/end_state`，不改权重、时段、事件数或末尾 padding。
- 缓存保存校正后的最终稿；恢复不再次生成或计费。有效稿保持原字节，重复
  校正不会累积内容。旧 node ID、输入输出、widget 顺序、示例工作流不改。

多人未指明归属、代词歧义、同句对应不同角色、合唱但未编号等情况，不能用
“最近名字”或统一 S1 猜测。保留完整稿并显示 `h3_missing_speaker` 等诊断；
已有 Quality Repair 仍可按原合同最多追加一次纠正。自动格式修复不是复杂
语义或成片质量通过；质量 Off 不进行整条创作检查，诊断标记 `contract_check`
未检查。Seedance 仍保持自然语言，不加入 H3 标签。
