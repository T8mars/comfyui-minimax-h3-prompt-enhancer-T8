# Qwen Image 2.1 编辑模式：真实 API A/B 验收

日期：2026-10-01。修复版本：1.28.2。结论：编辑专用模式更适合局部编辑、
多图角色分工和沿用原始画布；经典模式保留为默认，不替换旧工作流。
发现并修复了真实响应触发的降级与校验问题。**本报告评估提示词，不是生成图片质量。**

## 方法与证据边界

- 渠道：贞贞平价小屋；真实 `/v1/chat/completions` 和 `/v1/files/upload`。
  请求及返回模型均为 `qwen/qwen3.8-flash-next`。
- 同组采用相同原始图片、文字、最大字数、RGBA 设置和共享渠道配置；
  `max_tokens=8192`，流式返回，首次温度 0.7、纠正温度 0.1。
  云端请求未发送 seed，不声称同种子确定性对照。
- 每组一个探索性样本，每个模式最多首次生成加一次纠正。观察器记录实际响应，
  没有模拟 LLM 答案；测试完成后另外检查四个恢复输出完全一致且不再上传或生成。
- 图片包括原始 3027×1531 人物照片，以及合成的招牌 640×400、公园 960×540、
  服装 512×768、配色参考 640×640 和八张无关测试图。两模式共享同一组像素。
  各图片的原始尺寸、文件 SHA256、请求图片数量保存在外部原始证据中。
- 未安装或调用专用 PE；未调用绘图生成；未加载本地 GGUF 模型。
  RunningHub 生产发布/重载、成图身份保持、真实 alpha 通道及本地模型效果仍未验证。

测试经历并非一次无失败的运行：

1. `initial.json`：1.28.1 的完整 12 组 / 24 个输出、30 次逻辑生成。
   Edit-aware 仅 10/12 通过结构校验；尺寸文字与透明背景两组暴露下述问题。
2. 修复后有三次运行在上传阶段停止，分别记录于 `after-fix.json`、
   `after-fix-retry.json`、`fixed-continuation.json`。没有丢弃这些记录。
   后两次可见异常链为 ConnectionError → ProtocolError → TimeoutError；
   这些失败分支没有发起 chat，不会再次支付已完成的生成。现有证据不足以定位网络根因。
3. `fixed-final.json`：完整 12 组修复后 A/B，按相同运行时合同与输入恢复了之前
   已完成的两项，剩余请求均实际执行。Edit-aware 12/12、Classic 11/12 通过结构校验。
   Classic 的 60 字透明背景用例暴露了同类 JSON 包装降级问题。
4. 补修共享降级逻辑并以实际失败响应增加回归；`alpha-final.json` 再次真实运行
   两个模式。Classic 59 字通过；Edit-aware 首稿 75 字结构合格，纠正稿缺少明确
   背景说明，因此保留首稿并报警，**没有宣称满足 60 字目标**。

第 3、4 步使用测试器的 `--reuse-uploads`：重复素材复用本进程中真实上传成功的 URL，
并允许连接异常时额外重试一次上传。URL 只在内存中，不保存；每个素材仍由生产上传
函数实际上传。此选项不是生产上传策略变更，也不缓存或模拟生成答案。
因上传复用、跨运行恢复和云端波动，耗时不能作为严格速度对比。

## 真实暴露的问题与修复

| 问题 | 证据与处理 |
| --- | --- |
| 首稿 JSON 引号未转义，纠正稿仍带画布比例 | 原先降级返回首稿原始 JSON、空比例。现在取可解析的描述，仍标记未通过校验；编辑模式的显式 UI/文字尺寸仍可用，不伪造模型跟随决策。 |
| 中文 `透明背景RGBA图像` 被误拒绝 | 原判断只认“背景…透明”。补认“透明背景/底色”，保持对“不透明/不是透明/没有透明背景”的拒绝。Classic 原输出校验器未放宽。 |
| 降级草稿超长却报告未超长 | 按真实输出长度重新计算 `over_limit`；不强行截断固定文字或完整草稿。 |
| Classic 两次透明背景校验失败，提示词口返回 JSON 包装 | 共享降级解码可解析的非空描述，仍保留 `structured_response=false` 和失败原因，不把未校验比例当有效决策。正常 Classic 提示消息、校验器和四输出协议不变。 |

编辑模式纠正请求还明确重申 JSON 引号转义、精确 `<imageN>` 标签、画布元数据
与画面文字分离，以及语言/透明/长度约束需同时满足。没有第三次逻辑生成。

合并集的客观结果：

- 两模式各 12/12 有非空描述和结构合格输出；**结构合格不等于所有约束满足**。
  新模式短字数用例为 1/12 超长，`over_limit=true`、`repair_failed=true`。
- Classic 14 次、Edit-aware 15 次逻辑生成。所有 HTTP chat 状态为 200，均最多
  两次逻辑生成；恢复测试 24/24 完全一致且零新增 HTTP。
- 前八个沿用原图/目标画布用例，新模式均选择正确来源并保留原始比例；
  固定 UI、显式尺寸、扩图三种决策另测。10 图包括明确无关素材，并非遗漏上传。
- 服务端用量（含纠正）：Classic 96,177 token、Edit-aware 72,490 token；
  completion 分别 12,964 / 6,918。描述平均字数分别 1703.8 / 239.8。
  中文与英文字符数不可直接推成价格优势；此单次样本不足以保证固定节费比例。
- 新模式完整矩阵的 10 图组约 169 秒、短字数组约 137 秒；另一次短字数组约 21 秒。
  均非 token 用完而截断，不保证新模式每次更快，也不把耗时推测为某个网络根因。

非预设比例如 `3027:1531`、`8:5`、`4:1` 是画布规划结果，不自动裁切、拉伸或执行
扩图；下游只接受固定比例时需显式选支持的 UI 比例。静态 `referenced_images` 是
标签出现检测，不是语义参与判定：`<image2>至<image9>` 即使在否定句中，两个端点
仍会算被提及，不能将 `unreferenced_images` 当成准确的“无关图”数量。

## 文案效用评分（主观，不是成图分）

由 Codex 阅读实际输出和输入后评分，不是盲评、用户满意度或统计性基准。
五项满分分别为：编辑清晰度 25、保留边界 25、来源/画布 20、固定约束 20、

画幅冲突会扣分。最后一组按再次复测评分，不隐藏新模式的字数波动。
