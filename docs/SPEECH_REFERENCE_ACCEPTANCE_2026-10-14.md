# 语音参考：实施与验收记录（2026-10-14）

基线为本仓库 1.31.1。新增默认关闭的辅助节点、H3／Seedance 可选 lazy 接口及独立输出合同检查；没有替换原 API、GGUF 或视觉 Strata 路径。此轮未授权发布，未提交、推送或改版本。

以下是第一阶段冻结源码的历史测量，不覆盖后来检查发现的问题。用户追加的 20 轮交叉检查、时间偏移真实复测及后续修复见 [交叉检查记录](SPEECH_REFERENCE_CROSS_REVIEW_2026-10-14.md)；旧请求、评分和失败不改写。

## 测量边界

本机 Windows、Python 3.12.10、ComfyUI 0.39.0；最低 ComfyUI 0.33.0 的固定源码另做候选包隔离 CPU 加载。它不等于最低版本上的整套运行队列，更不等于 RunningHub 已部署。

真实增强使用用户已经启动的 Strata 服务，模型 `sc117-qwen3.8-flash-next-abliterated-iq3_s`，原生上下文 32768。主引擎与视觉进程在测量前后保持同一 PID、loaded/running 状态。没有调用启动、停止、卸载、切换模型或设备设置接口。

真实转写使用单独创建的随机端口 ASR-only 服务，复制已审查的 Strata Python 源码／CPU 运行组件，读取现有 Confucius4-R2T2 Q4 主模型、Q8 音频 projector 与 VAD；没有下载权重或写用户配置。其 chat 占位构造器未被调用，**转写由真实原生 ASR worker 完成**，不是伪造文本。每次 POST 的 `expected_device=cpu` 均以实际服务接收记录核验。

当前用户已运行实例仍是旧的 `0.1.42-t8.7`，没有新增 CPU-guard 声明；未为了验收擅自重启它。自动转写应使用包含本次服务端保护的版本，或更新后由用户自行重启；已有字幕离线路径不依赖这个保护。配套服务修改仅是原子 CPU 断言与回归，不改变不带新字段的旧客户端行为。

## 真实 ASR

| 检查 | 观测与判定 |
| --- | --- |
| 48k 双声道 AUDIO／AAC 文件 VIDEO | 三句已知合成中文全部识别，顺序正确。 |
| 视频裁剪＋额外窗口 | 按有效输入时间映射，没有把源起点重复加进 cue。 |
| 人工偏移 | 原词／数量不变，逐 cue 时间增加 250ms，仅一次。 |
| 数字静音／无音轨 | 分别返回 `silence`／`no_track`，不伪造对白。 |
| 低音量非零 | 确实进入识别，未按幅度阈值跳过为数字静音；这不证明低音量普遍识别准确。 |
| 12 秒文件／跨窗口整句 | 有效时窗正确，交叠窗口保留整句和同一 cue ID，不臆造逐词时标。 |
| 取消后新请求 | 实际观察 ASR worker，取消清理自有进程后下一次请求成功。 |
| 非零 PTS＋声音延迟 | 已知容器原点 5s、音频延迟 0.5s；实际解码时钟确认，未重复加 5s 或抹平音频延迟。 |
| 中英混合 | 本地已安装双语合成语音；Auto 模式保留“红色圆圈向右移动。”与“The background turns blue.”，未互相翻译。 |

共 12 类不同检查。最后两项分别独立追加，不改写首批结果。最后一项耗时 21.703 秒；服务自有 worker 退出，用户主模型及视觉实例不变。最终源码另做 48k 双声道真实转写，18.219 秒完成，三句与跨窗口处理再次通过，工作进程退出；不是把此前全部 12 类都称为最终源码重跑。这里只覆盖合成清晰语音，**没有**证明多人重叠、噪声、方言、音乐人声、说话人识别或通用 ASR 准确率。

补充错误路径：能力端点缺失（404）按缺少 CPU 保护硬停止；ASR 409 可能来自原子 CPU 断言拒绝配置切换，一律按冲突停止，不被 `continue_empty` 吞掉。这两项通过本地真实 HTTP 夹具复现，不能冒称实际运行服务发生过设备切换。原 chat 客户端状态分类保持不变。

## 创作对照：失败同样保留

四个固定案例：H3 与 Seedance 各一个“仅参考理解”、一个“保留原对白”。每案例开关两组、各两次，首批 16 份，不替换失败。

- 首批：16 次首发＋4 次既有语言纠正，机器检查 13/16。人工复核发现 7 份硬失败，只有 9 份可评分；其中包含未启用参考的旧默认样本。关闭态仍按兼容要求冻结，不能为了让对照表好看而改原路径。
- 第二批：只跑 8 份 On，8 次首发＋3 次既有语言纠正＋4 次语音合同纠正，共 15 次实际 chat，145.200 秒。机器通过 7/8，人工硬门通过 6/8。
- 第二批两项真实问题：一份 H3 在中文正文中夹完整英文说明而被漏检；一份 Seedance 的三组相邻花括号对白被旧源文本解析器连同动作说明误算为额外台词。声音分层中没有引号的旁白说明也需单独检查，不能只查 `<d>`。

相应修复只在新语音功能开启时生效：逐句检查描述语言，原生花括号对白优先解析，明确的旁白／对白陈述不留在环境音层；协议标记、否定句、环境非语言人声另有反例。每份最多一次独立语音纠正，仍不合格明确拒绝成功，不无限重试、不把失败候选缓存为完成。

人工评分采用四维 0–4：对白保真、语义有用性、原生格式、目标时序与镜头可用性。硬失败不评分；Off 的“对白保真”仅表示不虚构，不冒充 ASR 精度。实现者已见模式，属于探索性人工复核，**不是独立盲评**。第二批合格 6 份中多数维度为 4，H3 一份仍有 3 分项；不能外推为“所有创作任务更强”。

第三批只复测 H3／Seedance 保留对白两案例，各两次，共 4 份：4 次首发＋2 次旧语言纠正＋2 次语音合同纠正，共 8 次 POST，119.679 秒。机器 4/4，人工仅 2/4：H3 两份通过（第二份镜头可用性 3 分），Seedance 虽原词完整，但分别写成 `{}原句{}` 与中文引号，没有遵守本节点已声明的中文 `{对白}` 格式，作为格式硬失败保留。未以“引号也行”临时放宽合同。

第四批仅 Seedance 保留对白两次：2 次首发＋1 次语音纠正，共 3 次 POST，28.473 秒，人工 1/2。第二份的原生对白其实正确，但“当听到‘某句’时”这个时间条件被误判为新增发声，最终拒绝了正确候选。已按实际完整响应补回归：只分析即时发声归属，区分条件引用与新说出的句子，同时保留真正额外发声的反例；没有删除额外台词检查。

最后一批在最终源码上仅新跑 Seedance 保留对白两次，2 次首发、0 次模型纠正，共 20.090 秒，人工硬门 2/2。第一份的三个明确发声引号由本地白名单无损改成 `{原句}`；第二份初次即是原生花括号。评分分别为 **4/4/4/4**、**4/3/4/2**：第二份开场圆圈居中、之后却从左侧出发，且“瞬间／平滑过渡”表述含糊，仍需人工改镜头连续性。格式／锁词通过不等于创作完美。

五批合计 32 份初始生成，32＋9 次既有语言纠正＋7 次语音纠正＝**48 次真实 chat POST**。不含 ASR、GET、Comfy 队列、单元测试和离线回放；不同源码版本不可合成“最终通过率”，失败记录均保留。Writing seed 相同，不宣称底层采样已严格可控，也不是独立盲评。

最终输出门另回放此前 4 份 story、2 份合格 H3 和第四批两份被误拒的真实可见响应候选：8/8 原文不变通过、0 completion／网络。最终门 SHA256 为 `78cecf1c05d918bed60b1efc519b68980531df33f2dbb0d5caded8cd325a72f2`。这是冻结门的捕获文本回放，**不是最终源码重新生成完整 16 份 A/B**，也没有把此前已失败的调用改写为成功。
