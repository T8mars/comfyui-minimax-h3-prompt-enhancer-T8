## 结论

已将“土豆-情绪演绎（声画协同）”作为现有表演导演配置的第五项接入。
旧 AUTO、强化、关闭、极致、默认值、端口、主节点序列化及示例工作流不变。
它是另一种人物演法，不是替换极致或更高的表演强度；没有自动新增付费规划、
评分请求，也没有改成外部 Skill 的输出格式。

真实结果支持“可选择并传入新方法”，**不支持“全面提升、所有输出无问题”**。
较完整的输入中两种模式多数持平；新策略的声画约束仍是 LLM 指令，不是强制
执行器。有对白的 H3 请求建议明确启用已有的“质量纠正”，不会自动替用户打开。
这次没有生成 H3/Seedance 视频，没有验证本地 9B 或实际参考图上的效果。

### 实际缺陷与纠正结果

- 初版 23 份完整输出缺 canonical ASCII 说话人 ID（包括全角 `（S1）`），
  其中两份还有非英语 vocal-language 标签。极致完整 23/24，原生无问题 11/23；
  新策略完整 24/24，原生无问题 13/24。这不是创作胜率。
- 初版部分有对白的稿把 `overall_soundscape` 写成 `N/A`，存在“无环境音”与
  “整片静音”的歧义；含泪组一份稿还加入“像收到画外信息”的未授权触发。
  不能因为台词没改就把它们说成全部合格。
- 增加原生说明后八份均有完整稿，但五份仍缺 ASCII 说话人 ID。只有三份
  检查无问题；仅靠更强提示词不能保证格式。
- 显式质量纠正的四份最终稿均通过当前原生检查。含泪组追加一次模型纠正；
  微笑威胁和双角色组各有一次现有本地协议修正、没有追加模型请求；麻木组
  首稿通过。共五次逻辑请求，**不是每份必定调用两次**。
- 四份人工读稿均保留原句、角色声音/物件归属和声音许可。四个样本不能证明
  质量纠正总能成功；检查器自身明确未检查物理可行性、最终视频及完整复杂语义。
  失败仍按原有流程保留最后完整稿及失败状态，不冒充通过、不默认第三次生成。

## 创作评价与分数

首先检查原生结构、原句/说话人、事实、声音、时长/镜头/景别及结尾。
未过硬门不给创作分。输入已完整不要求增加转折，不按长度或形容词数量加分。
四维 0–4 的尺度见[方法说明](EMOTION_PERFORMANCE.md)：情绪质地、转折/残留、
声画协调、景别可执行线索；无对白的声画维度记 N/A，不能当作 0。

逐份探索性审阅记录在
[`tudou_emotion_review_2026-10-04.json`](../tests/fixtures/tudou_emotion_review_2026-10-04.json)。
48 槽中 23 份因原生问题不评分、1 份失败不补分、4 份纯机械反例不打情绪分，
20 份可评分。文本初读使用打乱的 E 标签，但初期排错已见模式，最终数值在
解码后记录，且评价者是实现者；**不是独立盲评，不作统计显著性或总体胜率结论**。

- 大部分合格情绪/残留/景别文本为 3/4（清楚），不是艺术质量满分。
  “含泪但不哭腔”“微笑仍有威胁”“明确爆发不变成微动作”在两种模式的多数
  稿中都能保留；这些对白稿的格式问题不因语义看起来好而消失。
- 极近景四份都保持眼眉范围及完全静音。新策略第一次的“呼吸带动眼睑”
  比直接眼眉线索不够具体，情绪/残留仅 2/4；另一次达 3/4。不能称组内全胜。
- Seedance 潜台词组两种模式都保留黄票右手、Bob 无反应、关系开放及原句。
  新策略有一份明确嘴唇开合和说后停留（声画 3/4），其他三份主要是低声语气
  指令（2/4）。这一小差异不足以证明显著收益。
- 无对白的等待/残留、Relay 等待→行动，多数为 3/4 持平。Relay 八份均被原
  编排器接受，等待、行走与对白留在对应 delivery 段；四份对白 Relay 中三份
  仍有原生说话人问题。JSON 能编译不是视频情绪/口型验收。
- 纯机械反例四份没有被加上表情、呼吸、人声或强制停住，不存在“情绪污染”
  的已观察样本。这只覆盖该合成反例，不是所有无人物任务的保证。

建议：保留两种模式供选择；新模式用于混合情绪、逐句演法及余绪连续性，
极致继续用于弱表演稿的因果/节拍重构。当前证据不支持替换旧默认、把新模式
标成必然更强，或为了显得不同而强迫重写。进一步比较须使用更弱但不含糊的
相同输入、更多样本及独立评审；成片效果需另行验收，不能拿文本分代替。

## 测试工具问题的披露

最早三份 HTTP 200 完整稿因离线检查函数调用参数错误被暂记 TypeError；修复
评价器后原稿离线复检，没有再次生成，原记录保留说明。诊断期间第四次请求
曾中断，未捕获完整稿；之后该槽新请求单独记录，未知中断请求不计作 A/B 样本。
保存第四份后 runner 的变量初始化错误导致停止，修复后 resume 跳过所有已存槽，
包括失败，不重复支付替换。新增离线回归覆盖整 48 槽、续跑与中断记录保持。

合成证据导出只用白名单，验证每份输出 hash，要求 48/8/4 三阶段槽数完整；
失败不能被过滤掉，导出文件不能覆盖。回归校验原稿 hash、阶段区别、审阅
不补分及凭据/headers/messages 禁入。本轮密钥只在进程内使用，不写入文件。
