# YuE2 ABC 空输出修复验收 / Empty ABC regression

日期：2026-09-11。范围：文本创作与 ABC 输出，不运行 YuE2 音频模型。

## 原因与修复

1. 原实现只检查／透传用户提供的 ABC；未填写乐谱时，full/melody 只写入下游请求的 `cot`，没有调用 LLM 作谱。因此输出为空与 API Key 无关。
2. 现在默认用已选云端／本地 LLM 作谱，full 含旋律与和弦，melody 不含和弦。已有 ABC 优先，off 不作谱；高级设置保留明确的「下游 YuE2 规划」选项。
3. 真实响应出现过标题非空、段落注释位置不同、声部和音符挤在同一行。仅对新生成的谱面整理这些格式，不改音符、和弦、时值或用户已有谱面。
4. 真实响应也出现过 4/4 小节共 40 单位、而非 32 单位。此类音乐结构错误仍会失败并请求一次定向修正，不通过删音符或空谱规避。

检查依据：[官方双声部 ABC 约定](https://github.com/multimodal-art-projection/YuE/blob/92a73cc7652fcc1f937855e4b765e0a0edd7ff2e/skills/yue2-music/references/abc-editing.md)。
这属于 T8 LLM 作曲扩展，不是 YuE2 模型自身规划；格式检查也不等于原生序列化器重建或实际听感验收。

## 实测配置与证据

- 渠道：贞贞平价小屋；模型：`bytedance/doubao-seed-evolving`；seed：314159。
- 要求：`流行pop, r&b`；严格保留原词；歌词语言控件选择中文，但原词为英文，验证严格保留优先。
- 四行英文原词，含 Verse / Chorus 标签和 CRLF 换行；输出必须逐字保留。
- 修复前分别真实调用 full / melody：每次 1 个请求，耗时 12.33 / 10.02 秒，两种 ABC 均为空。
- 初版补上调用后，真实 full / melody 测试仍失败；因此继续修复格式兼容，而非用单元测试通过冒充验收成功。
- 四份脱敏真实谱面已收录于 `tests/fixtures/yue2_abc_live_*.json`；回归同时覆盖格式整理成功及错误时值必须拦截。

## 如何使用

重启 ComfyUI 并刷新页面；已有 ABC 留空，选择 full 或 melody，运行后将右侧 `abc` 接到显示文本或下游乐谱输入。
`yue2_request_json.abc` 与 `abc` 输出必须完全一致。选择 off 或显式选择「下游规划」时留空是预期行为。
保存完整原词时，其语言优先于语言下拉框；要改写／翻译，应另选相应歌词模式，不会自动覆盖原词。

## 本地 GGUF：ABC 失败保留其他输出（2026-09-11 补测）

使用实际 `Qwen3.8-9B-heretic-uncensored.i1-Q6_K.gguf`，上下文 32768、
单次上限 4096、seed 0、关闭思考，llama.cpp b10436。只进行文字推理，不运行音乐模型。
共享渠道配置确实会覆盖主节点里的模型和 Token 值，不是参数漏传。

原始“渡口家书”主题实测复现了报错：`Ins` 的显示名称被写成
`Guzheng & Strings`，缩写为 `Ins.`；自动修正后仍没有符合固定表头。
初稿正常结束（`finish_reason=stop`，2238 个输出 Token），不能归因于 4096 截断。
同时还存在过长的小节、`% label:` 注释和声部内联音符等情况。
脱敏原始失败谱面见 `tests/fixtures/yue2_abc_local_9b_rejected.json`，不是合格样例。

修复仅整理已识别双声部的显示名称和注释格式，不改声部 ID、谱号、音符或时值。
真正不合格的谱面仍不送给下游，但不再丢弃已经完成的风格、歌词和请求 JSON。
报告及节点提示明确标记“部分成功”；JSON 不含坏谱，保留原 cot 设置供下游规划。
恢复按钮也能恢复部分成功的五个输出及提示，无需重跑。

两次新推理各执行风格、作谱和一次修正，共 3 次调用。原词连同 CRLF 逐字保留。
**本轮输出保全验收通过，9B 的两条新谱面严格验收仍失败**；不得把这两者混为一谈，
也不因此宣称 9B 已能稳定作出合格乐谱。修复提示名称不足以纠正真正的节奏错误。
